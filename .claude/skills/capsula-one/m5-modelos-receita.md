# Skill: Modelos de Receita & Captura de Valor (Modulo 5 — Capsula One)

## Quando usar
- Quando o usuario esta definindo como monetizar o produto
- Quando precisa precificar ou escolher modelo de receita
- Quando discute proposta de valor quantificada
- Quando avalia se deve mudar pricing ou modelo de negocio
- Quando esta preparando metricas para PMF (LTV, CAC, unit economics)

## Framework Core

### Pre-requisito: PSF Comprovado
Antes de discutir modelo de receita, e necessario ter Problem-Solution Fit. Sem produto que resolve problema real, nao ha valor a capturar.

```
Valor Gerado (proposta de valor) → Valor Capturado (modelo de negocio) → Receita
```

**Modelo de negocio = a forma como voce captura parte do valor que entrega ao cliente** (Porter, decada de 80).

### Etapa 1: Quantificar a Proposta de Valor

O valor DEVE estar alinhado com o que e PRIORITARIO para o cliente (identificado no PSF/entrevistas). Se voce oferece economia de dinheiro mas o cliente quer economia de tempo, nao ha sinergia.

#### 3 Formas de Gerar Valor

| Tipo | Descricao | Como Mensurar |
|------|-----------|---------------|
| **Mais barato** | Reduz custo para o cliente | Custo sem solucao - Custo com solucao = valor |
| **Mais rapido** | Reduz tempo de uma atividade | Tempo sem solucao - Tempo com solucao = valor |
| **Melhor** | Melhora qualidade/experiencia | Frequencia/qualidade sem vs com solucao |

#### Exemplos de Quantificacao

**Biosensor (mais barato):**
- Cliente: criadores de gado com 1000 vacas
- Sem sensor: perda media R$63 mil/ano por doencas
- Com sensor: perda cai para R$36 mil/ano
- **Valor quantificado: R$27/cabeca de gado**

**Senseable (mais rapido):**
- Cliente: fabricantes de brinquedos/calcados
- Sem solucao: 16 semanas para desenvolver produto
- Com solucao: 8 semanas (70% reducao em modelagem e comercializacao)
- **Valor quantificado: 8 semanas economizadas (50% do tempo)**

**Intouch (melhor):**
- Cliente: pais em periodo de gestacao
- Sem solucao: informacao sobre saude do bebe a cada 2 semanas (visita medica)
- Com solucao: acompanhamento continuo 24h
- **Valor quantificado: de esporadico para on-time**

#### Formula de Quantificacao
```
Situacao atual do cliente (sem voce) vs Situacao futura (com voce)
Gap = Valor que voce gera
```

Quanto mais TANGIVEL e MENSURAVEL, melhor para precificar.

### Etapa 2: Escolher Modelo de Captura de Valor

#### 4 Modelos Principais

| Modelo | Descricao | Exemplo |
|--------|-----------|---------|
| **Venda unica** | Pagamento one-time | Comprar software perpetuo |
| **Assinatura/SaaS** | Pagamentos periodicos recorrentes | Netflix, Spotify |
| **Taxa de transacao** | Fee sobre cada transacao intermediada | Marketplaces (Mercado Livre, Uber) |
| **Plataforma (hibrido)** | SaaS + taxa de transacao | Shopify (assinatura + % vendas) |

#### Modelos Complementares

| Modelo | Descricao | Exemplo |
|--------|-----------|---------|
| Venda + manutencao | One-time + suporte recorrente | Software enterprise |
| Taxa por uso/hora | Cobranca por tempo de uso | Consultorias, AWS |
| Licenciamento IP | Licenciar propriedade intelectual | Patentes, franquias |
| Consumiveis (Gillette) | Produto base barato + refis recorrentes | Impressora + tinta |
| Publicidade | Monetizar atencao do usuario | Google, Facebook |
| Dados/leads | Monetizar base de usuarios | LinkedIn Premium |
| Freemium + extras | Gratuito base + upgrades pagos | Planos de celular com extras |

### Evolucao de Modelos: Case da Musica

Demonstra como o MESMO PRODUTO pode ter modelos de captura diferentes:

```
CD (venda unica de album) → iTunes (venda unica por musica) → Spotify (assinatura de acesso)
```

A musica nao mudou — o modelo de captura e que foi disruptado a cada geracao.

**Tendencia macro:** Mercado de AQUISICAO → mercado de ACESSO (recorrencia). Facilitado pela cloud.

### Etapa 3: Testar o Modelo

**Modelo de receita tambem e HIPOTESE** — precisa ser testado com clientes reais.

Criterios para avaliar:
1. **O cliente fica mais feliz?** Modelo alinhado com situacao de uso
2. **Tem melhor retorno?** LTV maximizado
3. **O cliente aceita?** Willingness to pay comprovada
4. **E escalavel?** Custo marginal baixo para servir mais clientes

### Metricas-Chave pos-Modelo de Receita

| Metrica | Formula | Meta Early-Stage |
|---------|---------|-----------------|
| **MRR** | Soma de receita recorrente mensal | Crescendo MoM |
| **LTV** | Receita media por cliente x Tempo de vida | Quanto maior, melhor |
| **CAC** | Custo total aquisicao / Novos clientes | Quanto menor, melhor |
| **LTV/CAC** | LTV / CAC | > 3:1 para PMF |
| **Churn** | Clientes perdidos / Total clientes | < 5% mensal |
| **ARPU** | Receita total / Total clientes | Crescendo com expansao |

### Sequencia Completa de Validacao (Modulo 5)

```
1. Quantificar proposta de valor (gap antes/depois)
2. Definir modelo de captura (SaaS, transacao, hibrido?)
3. Precificar com base no valor quantificado
4. Testar pricing com clientes reais
5. Medir LTV e Churn
6. Testar estrategia de aquisicao (proximo modulo)
7. Medir CAC
8. Calcular LTV/CAC → Se > 3:1 = caminho para PMF
```

### Regras de Ouro
- **Valor percebido pelo cliente > custo** — senao nao compra
- **Capture parte do valor, nao todo** — se voce economiza R$27/vaca, nao cobre R$27
- **Modelo alinhado com uso** — mesma pessoa, situacao diferente = modelo diferente (Starbucks vs Nespresso)
- **Teste antes de escalar** — pricing errado mata mais que produto imperfeito
- **Recorrencia > venda unica** — para SaaS, sempre prefira modelos com MRR
- **Quantifique sempre** — "melhor" e vago, "50% mais rapido" vende

## Aplicacao ao Quayer
- **Proposta de valor quantificada:**
  - **Tipo:** Mais rapido + Melhor
  - Sem Quayer: dono responde WhatsApp sozinho, demora 15-30min por cliente, perde ~20% dos leads
  - Com Quayer: multioperador, respostas em <2min, perda estimada <5% dos leads
  - **Valor quantificado:** recupera ~15% dos leads que seriam perdidos + libera ~2h/dia do dono
  - Em receita: se barbearia fatura R$15k/mes, 15% de leads recuperados = ~R$2.250/mes de receita extra
- **Modelo de captura recomendado:**
  - **Primario:** SaaS (assinatura mensal por organizacao) — recorrencia, previsibilidade
  - **Secundario (futuro):** Taxa por mensagem ou por conexao WhatsApp adicional
  - **Expansao:** Freemium para atrair → upgrade para multi-operador/automacoes
- **Pricing hipotetico para testar:**
  - Starter: R$97/mes (1 WhatsApp, 2 operadores) — acessivel para barbearia pequena
  - Pro: R$197/mes (2 WhatsApp, 5 operadores, automacoes) — barbearia em crescimento
  - Business: R$397/mes (ilimitado, API, CRM avancado) — redes e saloes
  - **Ancora:** valor quantificado de R$2.250/mes torna R$97-397 uma decisao facil (ROI 5-23x)
- **Metricas para acompanhar:**
  - MRR (meta: R$5k em 6 meses com primeiros clientes)
  - Churn mensal (meta: <10% nos primeiros meses)
  - LTV estimado (ticket medio x 1/churn)
  - CAC (custo de aquisicao via influencer/Instagram)
  - LTV/CAC ratio (meta: >3:1 para validar PMF)
